01 · Актуальность

Справочник нужен в момент вопроса, а не после поиска

Учебный материал по C++ читают короткими сессиями и в нестабильной сети, а статический контент приложения нельзя исправить без новой сборки.

01

Высокая справочная нагрузка

C++ обширен: синтаксис, типы данных, алгоритмы, STL, ООП. Начинающему нужна короткая форма «определение — пример — ожидаемый вывод».

02

Короткие сессии и слабая сеть

Материал открывают в транспорте и между парами. Веб-справочники и обучающие платформы требуют подключения и часто подписки.

03

Контент без управления

Статьи, встроенные в приложение, устаревают. Исправление опечатки или добавление темы влечёт выпуск новой версии.

→
Решение: мобильный справочник с офлайн-кэшем и единый сервер, через который администратор обновляет пользователей и контент без пересборки приложения.

03 · Архитектура

Четыре компонента, один контракт — API

Единая точка доступа. Клиенты не открывают файл БД — только API.
Источник истины — сервер. Кэш мобильного заполняется ответами API.
Права проверяются на сервере, а не только скрытием кнопок в интерфейсе.

05 · Админ-панель

Управление пользователями и контентом без сборки приложения

  • Вход только с ролью admin. Обычному пользователю панель сообщает об отказе и завершает сеанс.
  • Пользователи: список, поиск, создание, редактирование, блокировка, смена роли.
  • Статьи: CRUD, категория, сложность, теги, блоки, публикация и снятие с публикации.
  • Категории: CRUD; удаление запрещено, пока в категории есть статьи.
  • Ошибки API адресны: 409 — у конкретного поля, 401 — возврат на вход, 403 — отказ.
Роли: admin — управление системой; user — опубликованный контент и только свои избранное, история и сниппеты.

08 · Итоги

Система готова к демонстрации и развитию

Достигнуто

  • четыре компонента системы
  • сквозной поток «публикация → приложение»
  • роли и проверка прав на сервере
  • кэш и обработка сетевых ошибок

Практическая значимость

  • готовый справочник для студентов
  • преподаватель управляет контентом
  • единый стек Dart для клиентов и сервера
  • основа для учебных проектов

Ограничения

  • SHA-256 вместо Argon2/bcrypt
  • HTTP без TLS в локальной демонстрации
  • SQLite в одном файле, без репликации
  • нет офлайн-очереди изменений
  • нет аудита и пагинации

Развитие

  • PostgreSQL и репозиторный слой
  • Argon2, JWT и refresh-токены
  • HTTPS, Docker, CI/CD
  • push-уведомления
  • офлайн-синхронизация и аналитика
